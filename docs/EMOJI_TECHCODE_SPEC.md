## 0. コンセプト（確定事項）

PenchantManufacture の図柄アセットを、**技術的テキストコードを装飾文字で組む**用途に運用する。

1. 日付時刻・モデル名・型番・数式・ソースコードなどを、工業デカール文字で 1 字 1 絵文字として並べる。
2. **複数行にわたり大量入力**できるよう、短縮された・機械的に推測可能なエイリアスを与える。

この 2 点が、以下の様式設計とグリフ提案の全判断基準となる。

## 1. プラットフォーム制約（様式の前提）

| 項目 | Misskey | Discord |
| --- | --- | --- |
| 名前の使用可能文字 | `^[a-z0-9_]+$`（**英小文字のみ**。add API 検証） | `[a-zA-Z0-9_]`（大文字可だが照合は実質大小無視） |
| 最小長 | 1〜（実質2以上推奨） | **2文字以上** |
| 大文字/小文字の区別 | **不可**（`A` は登録不可、`a` と衝突） | 名前は一意必須 → `A`/`a` は事実上衝突 |
| エイリアス | **あり**（複数可・補完に反映・一括zip対応） | **なし**（名前のみ） |
| 一括インポート | meta.json 付き zip | 不可（1点ずつ） |
| 1サーバ絵文字数 | 実質無制限（インスタンス依存） | 50〜（ブースト段階で増加） |

**設計上の帰結（確定）**

- 旧案の `pm_{variant}_{token}`（例 `pm_rust_A`）は **英大文字を名前に含むため Misskey で不正**。
  `A`/`a` が `a` に潰れ、技術テキストで必須の**大小区別が失われる**。→ 本様式で作り直す。
- 全プラットフォーム共通の最小公倍数は **「英小文字・数字・アンダースコアのみ / 2文字以上」**。
  これを名前の絶対規則とする。
- Discord はエイリアス非対応かつ点数制限が厳しい。→ **既定バリアント 1 種**のみを Discord 用に登録し、
  Misskey は全バリアント＋エイリアスをフル活用する二層運用にする。

## 2. 命名様式（字体コード・後置タグ方式）【確定】

### 2.1 中核アイデア（大量入力の成立）

Misskey の補完 UI で数百字を 1 字ずつ選ぶのは非現実的。**名前を文字から機械的に一意決定できる形**に
すれば、ユーザーはテキストエディタ上で `:n2p::n0p::n2p::n6p:` のように**組んで貼り付ける**運用ができる
（補完不要）。したがって様式の最優先要件は **決定論性（predictability）** と **短さ**。

### 2.2 構造（字体トークン＋後置タグ）

名前は **字体トークンを先頭**に置き、**プロジェクト＋バリアントを表す後置タグ**を末尾に付ける。
文字の識別子（何の字か）が先に来るため読みやすく、名前空間タグを最短化できる。

```
{字体トークン}{後置タグ}
```

- **字体トークン**: 字種を表す 1 文字のクラスマーカー＋値（固定幅）。マーカーが大小区別も兼ねる。
- **後置タグ**: プロジェクト印 `p`（Penchant）＋バリアント記号。既定バリアントは `p` の 1 文字のみ。

### 2.3 字体トークン規則（クラスマーカー方式・確定）

| 字種 | マーカー | トークン例 | 備考 |
| --- | --- | --- | --- |
| 数字 0–9 | `n` (number) | `n0`…`n9` | |
| 英小文字 a–z | `l` (lower) | `la`…`lz` | |
| 英大文字 A–Z | `u` (upper) | `ua`…`uz` | 小文字のみ環境でも大小を保持 |
| ギリシャ小文字 | （AGL） | `alpha`…`omega` | 数式で使う α β π μ 等を優先 |
| ギリシャ大文字 | `c`＋AGL | `calpha`…（`Δ`=`cdelta`） | 頻度低。明瞭さ優先で長め許容 |
| キリル大文字 | `yu`＋翻字 | `yua`…（`Ж`=`yuzh` / `Щ`=`yushch`） | BGN/PCGN 準拠の簡易翻字 |
| キリル小文字 | `yl`＋翻字 | `yla`…（`ж`=`ylzh`） | 同上 |
| 上付き / 下付き | `sup` / `sub`＋値 | `sup2` `subn` `supplus` | v3.1 で作者が作字 |
| ASCII 記号 | 2字略号 | 下表 | AGL 名も別名で付与 |

| 記号 | 略号 | 記号 | 略号 | 記号 | 略号 |
| --- | --- | --- | --- | --- | --- |
| `-` hyphen | `hy` | `.` period | `dt` | `:` colon | `co` |
| `/` slash | `sl` | `_` underscore | `sb` | `+` plus | `pl` |
| `=` equal | `eq` | `*` asterisk | `as` | `#` numbersign | `hs` |
| `@` at | `at` | `%` percent | `pc` | `&` ampersand | `am` |

| `{` `}` | `wo`/`wx` | `<` less | `sm` | `>` greater | `bg` |
| `!` exclam | `ex` | `?` question | `qm` | `,` comma | `cm` |

### 2.4 後置タグ（プロジェクト＋5バリアント）【更新】

既定バリアントは、**黒一色に限りなく近い near-monochrome・二画面（ダーク/ライト）両対応の新バリアント
`sumi`（墨）** とする。これは既存の二重縁取り（外ハロー→キーライン→ボディ）で、ライト/ダーク両地でも
輪郭が沈まない中立表示を狙うもので、技術テキストの本文用として最も汎用性が高い。既定なので後置タグは
`p` の 1 文字を占有する。工業4スキームはそれぞれ 1 文字を足す。

| バリアント | 和名 | 位置づけ | 後置タグ | 例（大文字 A / 数字 2） |
| --- | --- | --- | --- | --- |
| `sumi` | 墨 | **既定・二画面対応・近黒モノクロ** | `p`（既定） | `uap` / `n2p` |
| `rust` | 酸鉄 | 物理寄り・stencil | `pr` | `uapr` / `n2pr` |
| `hazard` | 警戒 | 物理寄り・stencil | `ph` | `uaph` / `n2ph` |
| `patina` | 緑青真鍮 | 物理×電脳・circuit | `pt` | `uapt` / `n2pt` |
| `nickel` | 白銅燐光 | 物理×電脳・circuit | `pn` | `uapn` / `n2pn` |

> `sumi` 配色（実装時の初期値・調整可）: ボディ 近黒 `#16181C→#0B0C0E`、キーライン/外ハロー
> オフホワイト `#E8E4D8`。暗地では白ハロー、明地では黒ボディが効き、両モードで視認できる。

**注記: バリアント非依存アセットの後置タグ**

スペーサ（完全透過の余白絵文字）のように **5 バリアントで見た目が変わらない**アセットは、
スキーム別に複製せず 1 組のみ生成し、後置タグは **プロジェクト印 `p` のみ**（バリアント記号を
持たない）とする。既定 `sumi` の後置タグと同形になるが、どのバリアントの字と混ぜても
`:upph::umph::spcp::n3ph:` のように後置タグの閉じ方が一貫し、打鍵リズムが崩れない利点を優先する。
実装は `scripts/glyph_tokens.py` の `NEUTRAL_SUFFIX`。

### 2.5 名前の実例

```
"2026-07-24"（既定=墨）→ :n2p::n0p::n2p::n6p::hyp::n0p::n7p::hyp::n2p::n4p:
"PM-3000"（既定=墨）    → :upp::ump::hyp::n3p::n0p::n0p::n0p:
"v1.005"（既定=墨）     → :lvp::n1p::dtp::n0p::n0p::n5p:
警戒色で "STOP"         → :usph::utph::uoph::upph:
酸鉄で "R2"            → :urpr::n2pr:
```

- 既定（墨）の最短名は **3 文字**（数字 `n2p`、`:n2p:` で 5 打鍵）。旧 `pmn2`（4文字）より短く、
  **字の識別子が先頭**に来るので目視でも追いやすい。
- 完全に決定論的なので、**エディタで一括生成→貼り付け**が可能（§5 の変換ツールで自動化）。
- 後置タグは `p` / `pr` / `ph` / `pt` / `pn` の閉じ記号として一貫し、トークン境界も明快。

### 2.6 エイリアス様式（Misskey）

各絵文字（正規グリフのみ実体化）に、検索性重視で以下を付与する。**名前は打鍵用に短く、
エイリアスは検索・可読用に多めに**、という役割分担。

1. 字体トークン（`ua` / `n2` / `hy`）と、その AGL 名（`A` の AGL、`hyphen`、`alpha` 等）
2. リテラル文字（小文字・数字・記号のみ。`é`→`e` 等の異体字も基底グリフの別名として展開／現行踏襲）
3. バリアント名（`sumi`/`墨`、`rust`/`酸鉄` など）— スキーム横断検索用
4. 用途タグ（任意）: `date` `code` `math` `unit` 等、後述カテゴリと連動

> Discord は名前のみ。既定（墨）の `..p` 名がそのまま `:n2p:` で使える。

### 2.7 カテゴリ構成（meta.json）

現行 `PenchantManufacture/工業デカール_{和名}/{字種}` を維持しつつ、字種サブカテゴリに
**上付き/下付き/合字/記号拡張**を追加（§4 のグリフ拡張に対応）。

## 3. Discord 運用の補足

- 230字 × 5バリアント = 1150 点は Discord の点数上限を大きく超える。**既定バリアント（墨）230 点**を
  基準とし、サーバのブースト段階・複数サーバ分割で運用する。
- 名前は `..p`（小文字・2字以上）で Discord 規則も同時に満たすため、**Misskey とワンソースで両対応**できる。

## 5. 補助ツール（大量入力の自動化）【スコープ内】

「複数行にわたる大量入力」を実運用するため、**文字列→絵文字コード変換**を実装する。

- `scripts/text_to_emoji.py`: 任意文字列とバリアント指定を受け、`:..p:` 連結文字列を出力。
  - 例: `text_to_emoji.py "PM-3000"`（既定=墨）→ `:upp::ump::hyp::n3p::n0p::n0p::n0p:`
  - 例: `text_to_emoji.py "PM-3000" -v hazard` → `:upph::umph::hyph::n3ph::n0ph::n0ph::n0ph:`
  - 未収録文字はスキップ＋警告。上付き記法（`^2`）・添字（`_2`）を A1/A2 絵文字へ変換するモードも付与。
- 併せて `docs/EMOJI_INPUT_CHEATSHEET.md`（名前対応表）を自動生成し、コピペ運用を補助。

## 7. 決定事項（確定済み）

1. **既定バリアント** = 新規 `sumi`（墨）。黒一色に近い near-monochrome、二画面（ダーク/ライト）両対応。後置タグ `p`。
2. **後置タグ** = プロジェクト印 `p` ＋バリアント記号（`sumi`=`p` / `rust`=`pr` / `hazard`=`ph` / `patina`=`pt` / `nickel`=`pn`）。
3. **字体トークン** = クラスマーカー方式（数字 `n`・小文字 `l`・大文字 `u` ＋値、ギリシャは AGL、記号は 2 字略号）。
4. **追加グリフ** = 本フェーズは様式確定のみ。将来候補として キリル文字（型番）／正方枠最大の大型演算子（Σ Π ∫）／科学単位特殊字（ℓ ℧ Å）／ß 以外の特殊合字 を記録。
5. **変換ツール** `text_to_emoji.py` = スコープに含める。
